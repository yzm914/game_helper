# 批量解压工具 (Batch Extractor)

一款基于 PySide6 的批量解压工具，专为资源收集场景设计。支持多层嵌套压缩包、RAR/旧式 ZIP 分卷、伪装文件识别，输出干净的目标目录结构。

## ✨ 功能特性

- 批量添加文件或文件夹（支持拖拽、多选）
- 递归解压压缩包内的压缩包，支持任意深度嵌套
- 分卷支持：旧式 ZIP 分卷（`.zip` + `.z01` 等）与 RAR/7z 分卷组（`.part1.rar`、`.001`），整组原子解压并整体清理
- 魔数检测识别改后缀的伪装压缩包（如 `.jpg` 实为 zip）
- 目录整理：统一包装目录折叠 + 同名嵌套合并，消除冗余层级，同时保留初始压缩包名
- 安全删除中间层压缩包，可移入回收站或永久删除
- 密码管理：DPAPI 加密存储，自动尝试解压带密码的压缩包
- 冲突处理策略：保留原目录 / 合并跳过 / 合并重命名 / 覆盖
- 深色主题界面

## 🚀 快速开始

### 运行环境

- Windows 10/11
- Python 3.9+（源码运行）或直接使用打包好的 exe

### 依赖安装（源码运行）

```bash
pip install -r requirements.txt
```

### 7-Zip 组件

程序需要 `7z.exe` 用于解压分卷（`.zip`+`.z01`、`.partN.rar`、`.7z.001`）与 RAR。请将 **`7z.exe` 与 `7z.dll` 一起**放到以下任一位置：

- 程序所在目录（推荐）
- 系统 PATH 中

> ⚠️ `7z.exe` 取自 7-Zip 安装包时**不是独立程序**，运行时必须能加载同目录的 `7z.dll`，否则会报 `Codec Load Error: 7z.dll : 找不到指定的模块`，所有分卷/RAR 任务都会失败。若想只用单个文件，请改用独立版 `7za.exe`（改为它，并把下面的 `7z.exe` 换成 `7za.exe`）。
>
> 预编译的 exe 已内嵌这两个文件，无需额外放置。

### 运行

```bash
python extractor_app.py
```

> 程序按脚本（或 exe）所在目录读写配置：`app_config.json` 记忆上次目标目录与选项，`passwords.json` 保存加密后的密码。
>
> 开发工作区中源码位于 `src/extractor_app.py`、解压器位于 `tools\`，配置随之落在 `src/` 下；本仓库使用平铺布局。开发工作区请用 `scripts\run-dev.cmd` 启动（它会把 `tools\` 加进 PATH，否则找不到 `7z.exe`）。

## 📦 打包为 EXE

```bash
pyinstaller --onefile --windowed --name BatchExtractor --add-binary "7z.exe;." --add-binary "7z.dll;." extractor_app.py
```

打包完成后，将 `7z.exe` 与 `7z.dll` 复制到 exe 同目录即可（若已用 `--add-binary` 内嵌则无需）。

## ⚙️ 使用说明

1. 选择目标文件夹
2. 添加压缩包文件或文件夹
3. 根据需要调整选项：
   - **目录策略**：`保留源文件夹名`（拖入文件夹时多套一层该文件夹的名字）/ `不保留源文件夹名`（默认，直接按包名输出）
   - **目标已存在时**：同一个包再解压一次（或新版本要覆盖旧版本）时的处理方式——保留原目录（另建副本）/ 合并（同名保留旧的）/ 合并（同名自动改名）/ 覆盖
   - **删除中间层**：解压完成后删除中间压缩包，避免冗余（你添加的原始文件永不删除）
   - **移入回收站**：开启后删除的文件进入回收站，可恢复
4. 点击“开始解压”

## 🗂️ 目录整理逻辑

所有解压完成后执行：

1. **包装目录折叠**：消除所有“只包含单个子文件夹”的无意义中间目录
2. **同名嵌套合并**：合并父目录与子目录同名的冗余结构

最终保留初始压缩包名的顶层目录，内部直接包含实际内容。

## 🔒 密码存储安全

密码使用 Windows DPAPI 加密后存储在 `passwords.json` 中，仅当前 Windows 用户可解密。请勿将此文件分享给他人。

## ⚠️ 已知限制与注意事项

- **你添加的原始压缩包永远不会被删除**：「删除中间层压缩包文件」只清理解压过程中**从压缩包里解出来的**中间层，你自己下载的那些文件始终保留。
- **目录整理会遍历整个目标文件夹**，不只是本次解压的产物——上一次运行遗留的目录也会被折叠/合并。建议每次换新目录或先清空。
- **`保留原目录` 的副本会保留原有嵌套**：重复解压同名包时新产物落在 `包名(1)\`，内部层级与你第一次解压时完全一致。
- **合并类策略会改动已有文件**（`合并（同名保留旧的）` 会丢弃新包里的同名文件，`覆盖` 会用新文件替换旧文件）。不确定时先用 `保留原目录`，它只新增、不改动。
- **密码加密与 Windows 用户绑定**：DPAPI 密文换用户或换机器后无法解密，需要重新录入。
- **自 v2.1.0 起移除了 4 个无效控件**（递归模式、递归解压开关、智能提升单文件夹、全局去除冗余嵌套）：它们此前不影响任何行为。目录整理始终按上面的“包装目录折叠 + 同名嵌套合并”执行，递归始终开启。
- **RAR 分卷组（`.part1.rar` + `.part2.rar`）与旧式 ZIP 分卷（`.zip` + `.z01`）已支持**，带密码的分卷包会先尝试无密码、再按保存的密码逐个尝试。

## 🧯 启动报错 `could not create temporary directory`

单文件版是**自解包**程序：启动时先把运行时解压到 `%TEMP%`，然后才运行。这一步被挡住就会出现该提示（通常紧跟在 SmartScreen 提示之后）。常见原因与处理：

| 原因 | 处理 |
|---|---|
| 安全软件拦截“自解包并释放文件”的行为（火绒 / 360 / McAfee 等） | 把 `BatchExtractor.exe` 加入该软件的**信任区 / 白名单**；或在其弹出的提示里选“允许” |
| 程序所在目录带**低完整性级别**或只读策略（沙箱工具、企业策略会这样做） | 把 exe **复制到桌面或 D 盘**再运行——复制会丢掉该标记，新文件继承目标目录的正常级别 |
| `%TEMP%` 被清理工具锁住，或指向不存在的路径 | 新建一个目录，在命令行里 `set TEMP=D:\Temp` 后再启动程序 |

**兜底方案**：改用随附的**文件夹版** `BatchExtractor_onedir.zip`。它启动时**不解压任何东西**，因此完全不受上述限制；把它解压到 D 盘等普通目录，双击里面的 `BatchExtractor.exe` 即可（首次运行 Windows 可能提示“已保护你的电脑”，点“更多信息 → 仍要运行”）。
